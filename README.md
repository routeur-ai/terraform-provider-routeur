# Terraform provider for routeur.ai

Manage [routeur.ai](https://routeur.ai) configuration as code: workspaces,
projects, gateway API keys, provider credentials, models, routing rules,
safety policies (DLP, moderation, prompt shields, classifiers), budgets and
anomaly detectors.

The provider talks to the routeur.ai management API at
`https://app.routeur.ai/api/v1`. It manages configuration only; your
applications keep sending AI traffic to `api.routeur.ai`.

- Documentation: [registry.terraform.io/providers/routeur-ai/routeur](https://registry.terraform.io/providers/routeur-ai/routeur/latest/docs)
- Changelog: [CHANGELOG.md](CHANGELOG.md)

## Usage

```hcl
terraform {
  required_providers {
    routeur = {
      source  = "routeur-ai/routeur"
      version = "~> 0.1"
    }
  }
}

# API token (rtm_…) from app.routeur.ai, Settings → API tokens:
#   export ROUTEUR_TOKEN="rtm_..."
provider "routeur" {}

resource "routeur_workspace" "payments" {
  slug = "payments"
  name = "Payments"
}

resource "routeur_project" "checkout" {
  workspace_id = routeur_workspace.payments.id
  slug         = "checkout"
  name         = "Checkout"
}
```

The [provider documentation](https://registry.terraform.io/providers/routeur-ai/routeur/latest/docs)
covers authentication, a complete getting-started configuration, importing
existing configuration, and every resource and data source.

## Requirements

- [Terraform](https://developer.hashicorp.com/terraform/install) 1.0 or later
  (1.11 or later for write-only provider keys, `key_wo`).
- A routeur.ai organisation and an API token.

To build the provider: [Go](https://go.dev/doc/install) (version in
[`go.mod`](go.mod)).

## Development

```sh
make build      # go build ./...
make install    # install the provider binary into $GOPATH/bin
make test       # unit tests (no network, no account needed)
make lint       # golangci-lint (falls back to go vet)
make fmt        # gofmt
make docs       # regenerate docs/ from schemas, examples/ and templates/
```

`docs/` is generated by
[tfplugindocs](https://github.com/hashicorp/terraform-plugin-docs); never edit
it by hand. Change a schema's `MarkdownDescription`, an example under
`examples/` or a template under `templates/`, then run `make docs` and commit
the result. CI fails when `docs/` is stale.

To try a local build in a real configuration, point Terraform at it with
`dev_overrides` in a CLI config file (`TF_CLI_CONFIG_FILE` or
`~/.terraformrc`):

```hcl
provider_installation {
  dev_overrides {
    "routeur-ai/routeur" = "/path/to/your/go/bin"
  }
  direct {}
}
```

[`openapi/v1`](openapi/v1) is the published management API spec for the
routeur.ai platform version in [`openapi/VERSION`](openapi/VERSION). A unit
test checks that every field in the spec is mapped by the provider or
deliberately skipped.

The design and conventions every resource follows are in
[CONTRIBUTING.md](CONTRIBUTING.md).

## Acceptance tests

```sh
export ROUTEUR_TOKEN="rtm_..."
export ROUTEUR_ORG="your-test-org"
export ROUTEUR_BASE_URL="https://.../api/v1"
make testacc
```

Acceptance tests create and delete real objects, so `ROUTEUR_BASE_URL` must
point at a non-production routeur.ai environment; the tests refuse to run
against `https://app.routeur.ai`. routeur.ai maintainers run them before every
release.

## Releasing

Releases are tagged `vX.Y.Z`. The [release workflow](.github/workflows/release.yml)
builds and signs the release with [GoReleaser](https://goreleaser.com) and
publishes it as a GitHub release, which the Terraform Registry picks up.
Signing uses the GPG key in the `GPG_PRIVATE_KEY` and `PASSPHRASE` repository
secrets; its public half is registered with the Terraform Registry, which
accepts **RSA** (or DSA) keys only.

Versions follow semver. After 1.0, schema changes are additive only within a
major version.
